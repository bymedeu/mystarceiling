## Bounded catalogue appearance and accepted approximations

Owner direction: prepare common high-precision RGB, retain separate magnitude,
and move common-position preparation into building. Native values need not be
recoverable from the binary; retain source CSVs. Omit the two Hipparcos diagnostic
metadata fields from the binary. Skip invalid source rows with warnings.

The owner accepts colour/motion model errors for the current star-ceiling scope;
calibration campaigns and astrometric accuracy upgrades are later work. AI
explained the trade-offs, inspected existing acquisition/rejection/motion paths,
and recorded the [canonical decisions and deferred work](../decisions/ceiling-product-output.md#accepted-catalogue-preparation--2026-10-25).
Only documentation changed; converters, motion code and binary schema are unchanged.

## Initial RGB8 preparation and display implementation

The owner selected integer RGB storage, sRGB and source-specific temperature
conversion, accepting uint8 visual precision to limit memory. AI implemented
converters, complete binary-v3 records, build-time J2016 preparation and compact
RGB attributes with one display transfer. Magnitude remains double precision;
advanced colour and astrometric accuracy remain deferred. Canonical details and
limitations are in the [colour](../decisions/stellar-colour.md),
[catalogue](../decisions/catalogue-integration.md#current-prepared-catalogue--2026-10-25)
and [M2](../milestones/m2-ceiling-appearance.md#initial-part-2-colour-implementation--2026-10-25)
records. A second AI agent reviewed the boundary and verified offscreen pixels.
No owner visual acceptance or milestone closeout is claimed.
